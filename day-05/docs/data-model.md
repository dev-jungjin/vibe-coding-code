# 5일차 데이터 모델 — 게시글(Post)

이 문서는 바이브코딩 자유게시판이 다루는 데이터 모양과, 그 데이터를 읽고 쓰는 방법을 정리합니다. 오늘은 데이터베이스를 켜지 않고 **메모리 저장소** 로 같은 모양을 연습합니다. 6일차에 Prisma 와 Supabase 로 바꿀 때도 필드 이름은 이 설계를 따릅니다.

---

## 1. 핵심 용어를 쉬운 말로

| 용어 | 이 프로젝트에서의 의미 |
| --- | --- |
| 데이터베이스 | 글을 오래 보관하는 창고. 지금은 아직 없고, 서버 메모리만 사용합니다. |
| 테이블 | 같은 칸 구성을 가진 표. 게시판의 글 목록이 하나의 표입니다. |
| 행(레코드) | 표의 한 줄. 글 하나가 행 하나입니다. |
| 스키마 | 표에 어떤 칸이 있는지, 칸의 종류와 규칙을 적어 둔 설계도입니다. |
| API | 화면과 저장소가 약속한 주소와 방법입니다. JSON 으로 요청하고 응답합니다. |
| REST | 주소와 HTTP 메서드(GET, POST, PATCH, DELETE)로 자원을 다루는 약속입니다. |
| CRUD | 만들기(Create), 읽기(Read), 수정(Update), 삭제(Delete) 네 가지 기본 동작입니다. |
| ORM | 표에 대한 작업을 프로그래밍 언어의 함수로 바꿔 주는 도구입니다. 6일차의 Prisma 가 해당합니다. |

---

## 2. Post 필드

`src/types/post.ts` 와 `prisma/schema.prisma` 가 같은 이름을 사용합니다.

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `id` | 문자열 | 글을 가리키는 고유 값. 초기 데이터는 `welcome` 처럼 읽기 쉬운 아이디, 새로 작성한 글은 UUID 입니다. |
| `title` | 문자열 | 글 제목. 필수, 최대 80자. |
| `content` | 문자열 | 본문. 필수, 최대 5000자. 빈 줄로 단락을 나눕니다. |
| `author` | 문자열 | 작성자 표시 이름. 필수, 최대 40자. |
| `category` | 문자열 | 분류. 비우면 `일반` 입니다. |
| `createdAt` | ISO 날짜 문자열 | 처음 작성된 시각. |
| `updatedAt` | ISO 날짜 문자열 | 마지막으로 수정된 시각. 처음 작성 시 `createdAt` 과 같습니다. |

기본 키는 `id` 하나입니다. 지금은 사용자 테이블이 없어서 `author` 는 그냥 이름 문자열입니다. 9일차에 로그인을 붙이면 작성자 아이디를 따로 연결합니다.

6일차 익명 게시판에서는 수정·삭제 확인용 비밀번호가 추가될 예정입니다. 초안 스키마에는 주석으로만 남겨 두었습니다.

---

## 3. CRUD 와 API 의 대응

| 동작 | HTTP | 경로 | 저장소 함수 | 화면 |
| --- | --- | --- | --- | --- |
| 목록 읽기 | `GET` | `/api/posts` | `listPosts()` | `/` 목록. 서버가 저장소를 직접 읽습니다. |
| 상세 읽기 | `GET` | `/api/posts/[id]` | `getPost(id)` | `/posts/[id]`. 서버가 저장소를 직접 읽습니다. |
| 작성 | `POST` | `/api/posts` | `createPost()` | `/posts/new` 폼이 JSON 을 보냅니다. |
| 수정 | `PATCH` | `/api/posts/[id]` | `updatePost()` | 상세 페이지의 수정 폼이 JSON 을 보냅니다. |
| 삭제 | `DELETE` | `/api/posts/[id]` | `deletePost()` | 상세 페이지의 삭제 버튼이 호출합니다. |

작성 요청 본문 예시:

```json
{
  "title": "첫 글입니다",
  "author": "홍길동",
  "category": "질문",
  "content": "REST API 와 데이터베이스의 차이가 궁금합니다."
}
```

성공하면 상태 코드 `201` 과 함께 `{ "post": { ... } }` 를 받습니다. 제목이나 본문이 비어 있으면 `400`, 없는 아이디를 조회하거나 수정·삭제하면 `404` 입니다.

## 4. 메모리 저장소와 이후 계획

- 오늘 저장소는 `src/lib/mockStore.ts` 입니다. 서버 프로세스가 살아 있는 동안만 글을 기억합니다.
- `globalThis` 에 배열을 넣어, 개발 모드에서 파일이 다시 로드되어도 같은 배열을 재사용하도록 했습니다.
- 개발 서버를 완전히 종료하면 직접 작성·수정·삭제한 내용은 사라지고, 처음에 준비해 둔 글로 돌아갑니다.
- `prisma/schema.prisma` 는 6일차를 위한 초안입니다. 아직 `prisma generate` 나 마이그레이션을 실행하지 마세요. Supabase 프로젝트를 만든 뒤에 연결합니다.

화면은 이미 CRUD 가 됩니다. 다음 회차의 과제는 저장소만 진짜 데이터베이스로 바꾸는 일입니다.
