# 2일차 프롬프트 모음 — 목표 · 제약 · 예시

2일차 실습의 핵심은 "예쁜 소개 사이트 만들어줘"처럼 두루뭉술한 지시 대신, **목표(Goal)**, **제약(Constraint)**, **예시(Example)** 세 가지를 갖춘 프롬프트로 Claude Code에게 일을 시키는 것입니다.

아래 프롬프트는 실제로 이 `day-02` 사이트를 만들 때 사용한 지시문입니다. 수강생은 그대로 쓰거나, 자신의 프로필·프로젝트 내용만 바꿔 연습하면 됩니다.

---

## 두루뭉술한 지시의 문제

다음처럼만 요청하면 AI는 범위를 스스로 넓힙니다. 무거운 애니메이션, 불필요한 라이브러리, 데스크톱 전용 고정 폭 레이아웃이 섞이기 쉽습니다.

```text
나를 소개하는 예쁜 사이트 만들어줘.
```

같은 요청을 3요소로 나누면 결과물의 오차가 줄어듭니다.

---

## 프롬프트 1. 다중 페이지 골격과 공통 내비게이션

**목표**: 1일차 단일 페이지를 홈·소개·프로젝트 세 페이지로 확장하고, 모든 페이지에서 같은 메뉴로 이동할 수 있게 만든다.

**제약**: 순수 HTML/CSS만 사용하고, 모바일 퍼스트 반응형을 처음부터 적용한다.

**예시**: 메뉴 이름은 홈 / 소개 / 프로젝트이며, 현재 페이지 메뉴는 채워진 알약 모양으로 구분한다.

```text
day-01 자기소개 페이지를 확장해 day-02 다중 페이지 정적 사이트를 만들어 주세요.

[목표]
- index.html(홈), about.html(소개), projects.html(프로젝트) 세 페이지로 구성합니다.
- 모든 페이지 상단에 동일한 반응형 내비게이션을 두고, 세 페이지를 서로 연결합니다.
- 1일차의 프로필, 책, 반려동물 정보는 홈(index.html)에 그대로 살리되, 메뉴에서 다른 페이지로 이동할 수 있게 합니다.

[제약]
- 외부 JavaScript 라이브러리나 CSS 프레임워크는 사용하지 않습니다. 순수 HTML과 CSS만 사용합니다.
- 디자인 가이드는 같은 폴더의 design.md 를 따릅니다. 색상은 #1E2530, #00D4EA, #F4F5FB, #FFFFFF 이고 카드 모서리는 18px, 서체는 Pretendard 입니다.
- 처음부터 모바일 퍼스트 반응형으로 작성합니다. 고정 폭(width: 500px 등)은 금지합니다.
- 기본(768px 미만)은 단일 열, @media (min-width: 768px) 에서 2열로 확장합니다.
- 파일명과 경로는 영문 소문자 케밥케이스만 사용합니다.

[예시]
- 내비게이션은 모바일에서 로고와 메뉴가 위아래로 쌓이고, 메뉴 3개는 가로로 나란한 알약 버튼입니다.
- 데스크톱에서는 왼쪽에 로고, 오른쪽에 메뉴가 붙는 한 줄 헤더입니다.
- 현재 페이지 메뉴는 배경이 #1E2530, 글자는 흰색인 활성 상태로 표시합니다.
- 홈 레이아웃은 1일차와 같이 모바일 1열, 데스크톱은 왼쪽 320px 프로필 + 오른쪽 본문입니다.
```

## 프롬프트 2. 소개 페이지 내용 구조

**목표**: 강사 소개, 강의 원칙, 기술 스택, 최근의 일을 담은 소개 페이지를 만든다.

**제약**: 홈과 같은 디자인 토큰·헤더를 재사용하고, 새로운 CSS 프레임워크를 추가하지 않는다.

**예시**: 원칙은 2열 카드, 최근의 일은 세로 타임라인으로 보여 준다.

```text
about.html 소개 페이지에 아래 내용을 채워 주세요.

[목표]
- 짧은 소개 문단, 강의에서 지키는 원칙, 다루는 기술, 최근의 일을 담습니다.
- 왼쪽(데스크톱)에는 프로필 카드와 프로젝트/홈으로 가는 버튼을 둡니다.

[제약]
- style.css 와 홈 페이지의 헤더·카드 스타일을 재사용합니다. 새 색상이나 다른 폰트를 추가하지 않습니다.
- 모바일에서는 모든 블록이 한 줄로 쌓이게 합니다.
- 사실과 다른 회사명, 연도, 학력을 만들어 넣지 않습니다.

[예시]
- 원칙은 "처음부터 모바일 퍼스트", "지시문은 3요소로", "같은 서비스 위에 쌓기", "보이는 결과로 확인하기" 네 장의 카드입니다.
- 데스크톱에서 원칙 카드는 2열 그리드입니다.
- 최근의 일은 점과 세로선이 있는 타임라인으로, 각 항목에 시기 / 제목 / 설명 순서로 적습니다.
```

## 프롬프트 3. 프로젝트 목록 카드 그리드

**목표**: 프로젝트 네 개를 같은 형식의 카드 그리드로 보여 준다.

**제약**: 카드 정보 순서를 프로젝트명 - 설명 - 사용 기술 - 링크로 통일한다.

**예시**: 모바일 1열, 768px 이상 2열. 기술은 회색 알약 태그로 나열한다.

```text
projects.html 에 프로젝트 목록을 만들어 주세요.

[목표]
- 수업과 연결된 프로젝트 4개를 카드로 보여 줍니다.
  1) 바이브코딩 풀스택 웹개발 과정
  2) 다중 페이지 자기소개 사이트 (이 사이트)
  3) 바이브코딩 자유게시판 (4일차 예고)
  4) GS Retail 토큰 기반 반응형 UI

[제약]
- 각 카드의 정보 순서는 반드시 "분류 태그 - 프로젝트명 - 한 줄 메타 - 설명 - 사용 기술 - 링크" 입니다.
- 모바일은 1열, @media (min-width: 768px) 에서는 2열 그리드입니다.
- 사용 기술은 pill 형태의 태그로만 표시합니다.

[예시]
- 카드 상단에 작은 청록 분류 태그(예: "2일차 실습")가 있습니다.
- 제목은 16px, 굵게, #1E2530 입니다.
- 링크는 카드 하단에 텍스트 링크로 두고, 실제 이동이 없는 항목은 링크 대신 안내 문구를 넣습니다.
```

## 프롬프트 4. 점진적 수정 요청 예시

사이트를 한 번에 완성하려 하지 않고, 브라우저로 확인한 뒤 아쉬운 지점만 고쳐 달라고 요청하는 연습입니다.

```text
내비게이션을 조금 다듬어 주세요.

[목표]
- 스마트폰에서도 메뉴 세 개가 한 줄에 들어오고, 손가락으로 누르기 쉬워야 합니다.

[제약]
- 햄버거 메뉴나 JavaScript는 추가하지 않습니다.
- 기존 색상 토큰과 활성 메뉴 스타일은 유지합니다.

[예시]
- 모바일에서 각 메뉴는 가로로 동일한 너비를 가진 알약 버튼이고, 위아래 여백이 10px 정도입니다.
- 768px 이상에서는 메뉴가 내용 너비만큼만 차지하고 로고 오른쪽에 붙습니다.
```
